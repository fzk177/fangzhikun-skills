# 分析与原型

仅在阶段一读取本文件。

## 只读分析

1. 从用户请求中提取唯一纯数字任务 ID；无法唯一确定时先询问，禁止猜测成项目或迭代 ID。
2. 执行只读检查：

   ```bash
   node "${CODEX_HOME:-$HOME/.codex}/skills/zentao-task/scripts/inspect_zentao_task.js" \
     --task <任务ID> \
     --vault "<vault目录>" \
     --json
   ```

3. 检查任务、需求、备注和附件；若本地任务文件缺失，先用所属迭代 ID 执行 `sync_zentao_project.js --execution <ID>` 预览，方案确认后才可追加 `--apply` 建立本地资料。
4. 检查目标仓库适用的 `AGENTS.md`、当前分支、工作区状态和最近基线提交。工作区已有修改属于用户。
5. 代码范围按项目上下文选择：前端任务只允许修改前端、后端只读核对；后端任务反之；未标明或明显跨端时同时只读分析，并在方案中确认修改边界。
6. 完整阅读任务直接上下游，按实际范围核对数据入口、转换、保存、详情、审批、快照、导出、附件和校验影响，不读取无关模块。
7. 输出方案必须包含：需求理解、验收口径、数据流、拟修改文件、接口与数据库影响、项目资料维护项、上线与回滚、风险、分支方案和验证方式；原型存在时按下文单独汇报。
8. 首轮不得编码。完整展示方案后等待确认，提示回复 `$zentao-task 确认`；有异议时让用户直接描述。

## 原型识别与确认

1. 从任务、需求、备注和附件识别蓝湖、Lanhu、Figma、Axure、墨刀、即时设计、MasterGo、Sketch、原型或设计链接、页面截图、交互稿、图片、PDF 和设计标注。
2. 发现原型后不得默认访问，也不得在未阅读时声称结论来自原型；除非用户本次已明确要求阅读，否则先展示来源并提供：

   ```text
   检测到需求中包含原型资料：<平台、链接或附件摘要>

   1. 阅读原型，并按原型中的页面、交互和字段规则分析设计
   2. 不阅读原型，仅按需求文字和现有代码分析

   回复 $zentao-task 1 或 $zentao-task 2；有其他想法直接描述。
   ```

3. 用户选择前可继续与原型无关的只读基线检查，但不得形成字段位置、控件类型、尺寸、必填性、禁用或交互方式等依赖原型的最终结论。
4. 用户选择阅读后，只读取本任务相关页面、画板、状态和标注，并按实际范围核对：页面入口、字段位置、控件类型、字段文案、必填性、默认值、长度限制、可编辑或禁用条件、动态显隐、校验提示、按钮与弹窗、新增/编辑/详情差异及 PC/移动端差异。
5. 原型需要登录时先执行蓝湖钥匙串流程；邀请权限、验证码、客户端限制或自动登录后仍无法访问时，说明具体原因，并只索取以下任一种最小资料：公开或已授权链接、相关状态截图、导出的 PDF/图片/标注，或页面名、画板名、版本和交互说明。

## 蓝湖访问

蓝湖未登录或要求重新登录时执行：

```bash
node "${CODEX_HOME:-$HOME/.codex}/skills/zentao-task/scripts/lanhu_prototype_access.js" \
  --url "<蓝湖原型链接>" \
  --output-dir "<系统临时目录>"
```

- 脚本只从本机 `runtime.json` 的 `prototype.keychainService` 对应 macOS 钥匙串读取账号和密码；禁止把账号、密码、Cookie、会话令牌或验证码写入 Skill、脚本、命令参数、日志、业务仓库或 Obsidian。
- 成功后读取脚本摘要、`page.html` 和 `page.png`，只核对本任务页面。
- 钥匙串条目不存在或不可读取时，只提示恢复本机配置对应条目，不要求用户在对话中提供密码。
- 出现短信或图形验证码、扫码、设备验证或账号风控时停止自动化，让用户自行授权或改为提供导出资料。

## 原型结论边界

- 多个页面或状态无法唯一对应任务时，列出已识别范围和缺口，等待用户指定；禁止用相似页面代替。
- 用户选择不阅读时明确记录“原型未读取”，把界面位置、控件、样式和交互标为推断或风险。
- 阅读后单独汇报来源、实际页面或画板、确认规则、无法确认项，以及对代码范围和验收口径的影响。
- 原型、需求、代码或用户规则冲突时逐项展示冲突和影响，等待决定；原型不能覆盖安全边界、数据一致性和受控写入流程。
- 原型确认只对最近一次展示的来源、版本和范围有效；任一变化后必须重新确认。
