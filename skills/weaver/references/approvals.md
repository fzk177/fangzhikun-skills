# 逐条写入审核

## 审核单

每个实际请求采用以下格式，不合并不同请求：

| 项目 | 必填内容 |
|---|---|
| 编号 | jobId、sequence、完整 requestHash |
| 环境 | 用户所选 dev/pre/prod 及物理环境键 |
| 操作内容 | HTTP 方法、接口、对象 ID、实际字段和值；文件列名称、大小和内容摘要 |
| 操作目的 | 此次请求为什么必要，不能只写“按要求执行” |
| 影响范围 | 目标流程／节点／表单／记录／权限范围；新建后自动启用、全员发起等附加效果单列 |
| 已执行情况 | 之前已成功执行的请求，不能让用户误以为仍可整体取消 |

业务参数完整留在权限受限的本机 pending 文件；大文本及二进制以大小和摘要预览，审批前需要读取对应业务材料理解内容。凭证字段始终脱敏，不能把 token 放进审核摘要。

## 执行契约

`run` 进程停在当前请求，用户审核后 AI 才能调用 `approve --decision allow`。审核文件记录完整计划哈希、环境配置摘要、CLI 源码摘要和请求内容摘要；批准只用于当前唯一请求，发送前消耗批准。下一个请求必须重新生成审核单。

未知接口默认按非只读暂停，不能通过 `--read-only`、GET、名称前缀或临时环境变量放行。只读白名单只来自经核实的源码策略。

`deny`、超时或进程退出都不会发送当前请求，不撤销之前已执行的请求。写请求开始发送后任何网络异常都记为结果不明，不自动重放、不自动回滚。先用只读查询核对，再准备新操作。

运行记录保存在本机 state 的 `weaver/jobs`，文件权限 600、目录权限 700，不进入 Git。凭证不进入记录。不得编辑状态文件代替 `approve`。

## 本机持久写入

显式 `--out` 导出会先生成一条本机文件写入审核。官方 project 本地编码、编译、docx 转换、模板拷贝和 Skill 同步不由 OA 请求拦截器冒充已保护；这些动作应先展示实际文件、目的和影响并获得单独授权，再按官方指南执行。禁止用它们启动未受控的 OA 写请求。
