# 认证与会话续期

当前依赖的官方 CLI 使用 ETEAMSID。自动续期的实际行为是校验现有会话并在失效时重新账号登录，不等同于未经证实的 OAuth2 refresh_token。

## 一次性准备

1. 管理流程先预览 `weaver` 本机配置，用户确认后填写两套地址、CLI 包目录、钥匙串 service 和环境条目名。
2. 用户在自己的本机终端运行 `python3 scripts/enroll.py --env pre` 及 `--env prod`。账号和密码采用隐藏输入，传给子进程 stdin；不接受密码参数、环境变量或剪贴板。
3. 每个环境首次录入都需要用户在该命令提示中确认；替换已存在的条目必须显式传入 `--replace` 并再次确认。录入同时清空该环境的旧会话内容，防止沿用其他账号；不删除其他钥匙串条目。
4. 随后运行 `node scripts/weaver.js auth --env pre`。仅输出环境、认证是否有效和 CLI 版本，不回显账号、密码或 Cookie。

## 自动连接

- 首选环境对应的钥匙串缓存，向本环境 `teamsCheck` 发起身份校验。
- 兼容 `currentUser.employeeId`、`currentUser.id`、响应头和旧版嵌套字段，保存真实员工 ID，禁止以 unknown 或手机号替代。
- 缓存无效时从该环境的钥匙串取得账号密码，仅调用官方 AuthSession 的 RSA 登录实现，再以 `teamsCheck` 核验真实身份与租户。
- 限制认证请求到配置的 OA／认证中心及固定认证路径，不跟随未知域的跳转。
- 一次执行阶段只进行一次失效重登；密码错误、身份格式异常、验证码或多因素认证时停止。
- 缓存 session 写回钥匙串，不使用官方 CLI 的 `.key` 回退或磁盘 auth 文件。既有官方 CLI 配置与缓存不修改。
- `run` 注入内存 AuthSession；认证依赖不改变系统全局 profile。读请求失效后最多重新登录并重试一次；任何业务写请求都不自动重试。

## 限制

HTTP 环境沿用本机配置，不自动改成 HTTPS；RSA 登录由官方协议实现，但会话请求仍使用配置的传输协议。不能宣称传输已被 HTTPS 加密。

无人值守依赖已解锁、可访问的 macOS 钥匙串和服务端允许账号登录。OS 弹窗及服务端验证码不能由 Skill 绕过。自动登录尚需分别在真实环境完成只读核对，源码静态校验不证明已联调成功。
