# Obsidian 改动受控写回禅道

仅在用户明确要求把本地改动写回禅道时完整读取并执行本文件。普通“同步、更新、刷新迭代”均表示从禅道拉取到 Obsidian，不得触发写回。

## 强制流程

写回必须严格执行“预览 → 用户确认 → 哈希校验 → 更新 → 回读同步”，禁止跳过确认。用户首次提出写回时，即使措辞包含“更新”，也只能生成预览。

### 第一阶段：只生成预览

```bash
node "${CODEX_HOME:-$HOME/.codex}/skills/zentao-project-manager/scripts/push_zentao_changes.js" \
  --execution <迭代ID> \
  --vault "<vault目录>"
```

必须逐个展示对象、字段、禅道当前值和本地拟写入值，同时报告冲突、暂不支持字段、远端缺失对象、无基线警告和完整计划哈希。随后停止并等待用户明确确认。

### 第二阶段：确认后应用同一计划

```bash
node "${CODEX_HOME:-$HOME/.codex}/skills/zentao-project-manager/scripts/push_zentao_changes.js" \
  --execution <迭代ID> \
  --vault "<vault目录>" \
  --apply \
  --plan-hash <完整计划哈希>
```

- `--apply` 与 `--plan-hash` 必须同时出现。
- 当前计划与已确认哈希不一致时停止并重新展示差异。
- 确认只对当前计划生效一次；本地、远端或范围变化后必须重新预览。
- 字段级并发冲突禁止自动覆盖。
- 写回后立即用拉取脚本回读禅道，刷新本地来源字段和写回基线。
- 最后重新运行写回预览，待更新对象必须归零。
- 命令失败或校验未归零时，逐个回读计划对象，区分已生效、未生效和意外变化；禁止直接重试或假设全部未写入。

## 白名单字段

| 本地字段 | 禅道需求 | 禅道任务 |
|---|---|---|
| `title` | 名称 | 名称 |
| `priority` | 优先级 | 优先级 |
| `assignees` | 指派人，姓名唯一解析为账号 | 指派人，只允许一个账号 |
| `timeEstimate` / `estimatedHours` | 预计工时 | 预计工时 |
| `zentaoModuleId` | 所属模块 | 所属模块 |
| `storyId` | 不适用 | 关联需求 |
| `start` | 暂不写回 | 预计开始 |
| `due` | 暂不写回 | 截止日期 |

以下内容只报告，不自动写回：

- `stage`、`status`、`progress`、`completedBy`、已消耗工时和剩余工时。
- 需求描述、需求历史备注、任务描述及同步标记区外的本地正文。
- Project Manager 父子层级、标签、依赖和里程碑。
- 新建、删除、归档、关闭、状态流转及其他工作流动作。

增加写回字段或状态动作时，必须单独设计字段映射、必填参数和确认文案，禁止塞入通用 `update`。

## 基线与冲突

- 拉取脚本在 `customFields.zentaoPushBaseline` 保存本地和远端字段级基线。
- 解析 Frontmatter 必须兼容 YAML 块序列和单引号 JSON 字符串；禁止使用会跨行吞掉第一条序列值的 `:\s*` 正则。
- 只有本地值相对基线变化的字段才进入计划。
- 同一字段在远端也偏离基线时标记为冲突并拒绝覆盖。
- 无基线时显示醒目警告。普通字段与远端比较；任务日期使用拉取脚本相同映射推导兼容基线。
- `start = estStarted || realStarted || openedDate`。
- `due = deadline || estFinished || realFinished`。
- 只有本地日期偏离推导值且不同于远端当前值时才进入预览。
- 临时计划只保存在权限限制为当前用户的系统临时目录，不得写入 vault 或加入 Git。

## PUT 保护与校验

- 禅道需求和任务更新是 `PUT` 语义，请求必须携带接口支持的完整当前字段快照，再用已确认白名单差异覆盖。
- 用户预览和 `operation.fields` 只展示真正变化的字段，保护性字段不得伪装成用户改动。
- 请求前后校验非计划字段保持不变。
- 发现接口默认值覆盖时，使用写入前快照恢复，再完成回读和归零校验。

## 写回安全边界

- 仅允许通过 `push_zentao_changes.js` 执行现有需求和任务的白名单更新。
- 仅在用户确认计划哈希后允许执行 `zentao task update <ID>` 和 `zentao story update <ID>`。
- 禁止绕过脚本拼接 CLI 写命令。
- 始终禁止 `create`、`delete`、通用 `do`、`start`、`finish`、`close`、`activate`、`change` 等未纳入设计的写操作。
- 不读取、显示、记录或写入密码、Token 和钥匙串凭据。

## 写回结果汇报

预览时报告：

1. 每个对象的字段级“禅道当前值 → 本地拟写入值”。
2. 完整计划哈希、冲突、暂不支持字段、远端缺失和无基线警告。
3. 明确说明当前没有更新禅道，正在等待确认。

完成后报告：

1. 实际更新的对象数和字段数。
2. 回读同步结果。
3. 最终写回预览是否归零。
