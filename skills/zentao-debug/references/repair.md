# Bug 修复流程

仅在用户明确要求修复当前 Bug 时执行本流程；分析、定位或排查不授权修改代码。

1. 修改前记录每个涉及仓库的当前分支和工作区状态：

   ```bash
   git -C <repo> branch --show-current
   git -C <repo> status --short
   ```

2. 用初始状态区分本次 Bug 改动、用户已有改动和过程中出现的并发改动。保留不属于本次修复的修改；无法准确区分时停止提交准备并说明，不得覆盖、回退或纳入提交。
3. 前后端属于不同 Git 仓库时分别记录和处理，不得合并成一次提交。
4. 只修改与当前 Bug 直接相关的代码。排查阶段只读的前端代码，此时才可以按授权修改。
5. 修复后进行与改动相称的静态复核，不运行 Maven、Vue 或其他测试命令，也不自行补充测试。
6. 代码改动完成且没有剩余必需修改后，读取 `commit.md` 并进入 Git 提交核对；不得直接暂存或提交。
