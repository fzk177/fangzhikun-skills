# 泛微环境与审批操作

## 启用与依赖

- 仅在用户显式调用 `$weaver`、明确要求使用本 Skill，或已启用的 `$zentao-debug`／`$vesselhub-problem-analyze` 判断泛微审批流排查需要补充只读证据时启用。后者仅进入下面的“排查只读子流程”，不开放通用隐式调用。
- 内部依赖官方 `weaver-e10-builder`。完整读取其 `SKILL.md`，按需求读取其直接引用的指南；只有动作流任务才读取该依赖声明的 `generating-actionflows`。
- 保留官方应用、表单、字段、台账、工作流程、节点、操作者、条件、动作流、权限、页面、代码和 ESB 集成能力。业务实现由已安装的 `weaver-e10-builder` CLI 提供，不复制或改写第三方安装代码。
- 官方文档中的直接 `e10-cli` 命令统一改由本 Skill 的受控入口执行。官方默认权限、自动启用、自动发起范围、自动保存发布等行为不能覆盖本 Skill 的逐条审核规则。
- 官方依赖或 CLI 不存在、版本不匹配时明确报告，不自动安装或升级其他包。

## 排查只读子流程

- 由 `$zentao-debug` 或 `$vesselhub-problem-analyze` 进入时，仅查询能验证当前假设的泛微数据。复用调用方已确认的环境和业务关联线索；缺少环境先询问，不默认生产。`dev/pre` 共用测试环境，`prod` 独立，生产代码引用 `origin/pre` 不改变泛微查询环境。
- 仅使用受控入口与已核实的只读接口，不修改应用、流程、节点、操作者、表单、权限，不发起、撤回、通过、驳回或以其他方式推进审批，不执行持久导出、业务源码编辑或发布。
- 任何请求返回 `approval_required` 时，以对应任务 ID 和完整哈希调用 `approve --decision deny`，结束该请求并报告能力限制；不得调用 `approve --decision allow`，不得通过请求业务写入批准继续当前排查，也不得绕过入口或修改白名单。
- 自动认证和会话续期仅复用已配置的钥匙串凭证，不新增或替换本机真实配置及凭证；认证或查询能力不可用时报告阻塞并返回已有证据。审批实例、待办、审批日志能否查询仍以当前 CLI 与已核实接口为准，不编造命令。
- 输出查询环境、时间、条件、关联对象和最小脱敏结果；当前配置／状态不能代替故障时事实，空结果不能证明流程或业务数据不存在。调用方的代码修复或提交授权不扩大本子流程的只读边界。
- 下面的逐条写入审批流程仅适用于用户另行显式调用 `$weaver` 的操作任务，不能由本只读子流程转入。

## 环境规则

完整读取 [环境配置](references/environments.md)。每次执行都显式传入 `--env dev|pre|prod`：

- `dev` 和 `pre` 指向同一物理测试环境 `test`，共用同一套测试凭证和会话。
- `prod` 指向独立生产环境 `prod`；不得从测试环境推断或复用生产账号、会话或租户。
- 真实地址仅存本机 `runtime.json` 的 `weaver.environments`，禁止写入源码、变更记录和公开配置示例。
- 用户未指定环境时，先完成不依赖环境的分析，再询问；不默认生产，也不把“预发”当作独立服务器。
- 官方 CLI 根据域名生成的 profile 可能混用测试和生产，因此本 Skill 不使用其全局激活 profile 或磁盘凭证发现链。

## 只读与写入规则

完整读取 [逐条审核](references/approvals.md)。这是强制规则，不因任务紧急、批量操作、官方示例或之前批准过其他操作而放宽。

1. 按实际效果分类，不能用 GET/POST 判断只读；只有已核实的只读接口自动放行。生成 ID、加锁、启用、发布、导入、重排、增删改以及审批推进都属于非只读。
2. 每个非只读业务请求发送前必须逐条展示：操作编号及完整计划哈希、环境、操作内容与实际参数、操作目的、影响范围和可能追加的行为。
3. 用户必须明确批准该编号或哈希，才能调用 `approve`。沉默、超时、“继续看看”、任务总目标和对另一条请求的批准都不是本条授权。
4. 复合 CLI 命令中的每一个写请求都独立暂停、独立审核。创建后自动设置操作者、保存后启用、保存再发布等后续写入不能继承前一条批准。
5. 不绕过入口直接运行 CLI、curl、浏览器写入、SQL、第三方脚本或修改审核文件。不因接口名称像查询就直接添加只读权限；需先核对官方源码和接口语义，再在受控源码中更新白名单。
6. 网络错误或结果不明时不自动重试写请求；先只读核对是否已生效，再准备新的具体操作。已经执行的写入不会因后续拒绝而自动回滚。
7. 用户要求的本机源码、页面代码、导出文件等持久写入也要逐项说明和批准。运行入口对显式输出文件提供本机写入审核；业务源码编辑仍需先展示文件、目的和范围。

## 自动认证

按 [认证与续期](references/authentication.md) 执行：

- 首次账号密码由用户在本机隐藏输入，保存至 macOS 钥匙串；不经聊天、参数、环境变量、公开文件或日志传递。
- 已授权的认证初始化、会话校验、自动登录、失效重登和本机临时审核记录属于认证及执行设施，不修改 OA 业务数据，按用户对此 Skill 的预授权执行。
- 凭证和 ETEAMSID 会话都按物理环境隔离保存至钥匙串；钥匙串不可用时停止，不回退到明文或本机 `.key`。
- 使用当前 CLI 的 ETEAMSID 会话机制：先复用有效会话，失效时自动账号登录重新取得会话；没有证据时不声称存在 OAuth2 refresh_token 接口。
- 无账号密码、密码失效、验证码、多因素认证或不兼容的 SSO 会阻断免交互登录。报告阻塞点，不反复尝试密码，也不静默要求用户手工复制 Cookie。
- 认证失败后恢复读取可以自动进行；业务写入不能因续期而自动重放。重新操作仍逐条审核。

## 操作入口

以下脚本路径相对本 Skill 根目录，禁止从不可信数据中拼接 shell 命令：

```bash
node scripts/weaver.js info
python3 scripts/enroll.py --env pre
python3 scripts/enroll.py --env prod
node scripts/weaver.js auth --env pre
node scripts/weaver.js run --env pre -- workflow search --name 报销
node scripts/weaver.js run --env prod --purpose 调整已核实的审批人 --impact 指定流程的指定节点 -- workflow set-operator <流程ID> <节点ID> <人员关键词>
```

`run` 在进程中拦截 OA 请求，已登记只读请求立即执行；非只读请求输出 `approval_required` 并保持暂停。根据实际输出逐条向用户说明，用户批准后在另一进程执行：

```bash
node scripts/weaver.js pending --job <任务ID>
node scripts/weaver.js approve --job <任务ID> --hash <完整计划哈希> --decision allow
```

拒绝时使用 `--decision deny`。不得预先批准还未产生的请求。工具有后台 session 时保留该 session，收到用户决定后恢复它，不能重跑整个创建命令。

## 能力与结果边界

- 流程模板配置、表单数据及台账查询沿用官方能力；通用待办、审批实例、审批日志是否可直接查询以当前 CLI 与获授权的官方接口为准，不编造命令。
- 编码和文档分析只读取相关官方参考；代码编辑、编译产物、发布及导出持久文件均遵守逐项审批。原生流程与 Ebuilder 流程的资源 ID 不混用。
- 运行入口只支持官方原生命令和 fetch/ApiClient 传输，禁止子进程或其他 HTTP 通道绕过拦截；需要扩展传输时停止并按源码管理流程补充。
- 输出实际环境、已执行的读取/写入、批准编号、核对结果和限制；不能把保存当作启用，也不能把配置成功当作审批业务验收。
- 未经用户确认不新增或运行测试。静态校验通过不等于已连接真实环境或已验证自动登录。

## 配置与维护

只读查询无需业务批准。首次本机真实配置、凭证新增或替换、源码提交、推送、部署与升级遵循对应管理 Skill 的预览确认契约。

源码和脚本说明见 [配置与实现](references/setup.md)，只读接口边界见 [请求策略](references/request-policy.md)。
