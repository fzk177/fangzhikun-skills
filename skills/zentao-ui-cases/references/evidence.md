# 证据与判定标准

## 结论范围

UI 证据只支持直接观察及重新进入后可见的状态。例如“刷新后只有一条本次记录”不等于“后端接口幂等”，“保存后主从页面均可见”不等于“数据库事务原子”。人工/工具辅助项独立保留。

每项记录场景 ID、运行/版本、时间、环境、角色/租户、页面与对象身份、起始状态、脱敏输入及唯一标识、独立预期来源、实际表现、证据及副作用/清理状态。截图和 Trace 只在能支持结论的位置采集，避免与对象身份脱节的孤立图片。

对于保存和状态变更，成功提示不足以判定通过，需刷新、重新打开详情或重新进入后核对持久化结果。瞬时校验等不适用持久化的场景应明确原因，不为了凑等级捏造刷新结果。

## 证据等级

- E3：对象身份、前态、输入、即时结果、适用的刷新/重入检查均有证据。
- E2：对象身份、输入和可观察结果有证据，但部分上下文缺失；场景要求持久化时仍必须提供该证据。
- E1：仅提示、孤立截图或无法复核的叙述。
- E0：没有可用证据。

P0 通过要求 E3，其余通过至少 E2；低于要求应保持阻塞/未证实，不能自动降低期望。证据可引用相关截图、Trace 或可审阅的测试输出，不要求每一步都截图。生成器只能检查路径、分组和声明等级，内容真实性与是否对应当前对象/版本仍由执行者审阅。

## 判定

| verdict | 含义 |
| --- | --- |
| `Passed` | 范围内预期满足，证据达标 |
| `Failed` | 可观察预期被实际结果推翻；产品缺陷需进一步确认，环境/测试问题不自动算产品 Bug |
| `Blocked` | 前置、账号、数据、规则或证据不足，写明缺口 |
| `Not run` | 尚未执行或不在此次选定范围；不能算通过 |
| `Passed — human review required` | 明确的 UI 子断言通过，关联人工项仍开放 |

`ai_review` 的 UI 成功用最后一种判定。预期本身含糊时应 Blocked。skip/xfail/工具报错按真实原因对应 Not run/Blocked，保留原 pytest 状态，不能映射成 Passed。

浏览器可观察通过率 = 两类 Passed /（两类 Passed + Failed），展示分子/分母与原始数量；Blocked、Not run 和人工项另列数量及 P0 状态。没有已执行项时显示“不适用”，不输出 100%。执行完成不等于测试通过，UI 通过也不代表整个系统验收通过。

## 回归与阻塞闭环

固定回归覆盖本次改动和共享能力的高风险点；动态队列记录运行中发现的疑似缺陷、波动或副作用及纳入理由。在授权范围内处理，超范围则记录阻塞并说明需要的条件。

局部阻塞不必停止其他独立用例。是否重试取决于阻塞条件是否消除、前次副作用是否可确认以及授权范围；记录重试结果或不重试理由，不机械重放所有失败步骤。首次失败不被后续成功覆盖。

最终报告要求选定 AI 场景有最终判定、相关固定/动态回归有结果或明确阻塞、首次/最终阻塞均有后续处置、已确认缺陷有复现步骤和证据。仍有阻塞可形成完整事实报告，但结论保留限制；未执行的选定场景只能生成草稿。
