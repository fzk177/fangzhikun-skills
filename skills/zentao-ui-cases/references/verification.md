# 验证与组合晋级

## 默认静态检查

确认生成文件能被 AST 解析；按仓库现有命令执行 Ruff 检查和格式检查；检查本次关联的登记 ID、Python 符号、测试引用、依赖和需求映射。脚本可用 `scan_assets.py` 定位语法错误和真实入口。

静态检查不启动浏览器、不访问业务环境、不导入应用或测试。`pytest --collect-only`、导入 `conftest.py` 和项目启动都可能执行代码，不在默认范围内。未配置工具时说明缺失，不静默新增依赖来扩大框架。

## 授权后的实际执行

需要明确基准 URL、部署版本或其可核验依据、账号角色/租户、数据范围和清理方法，并已有执行授权。信息齐全且会话已授权时直接执行对应范围，不重复确认。不可把 Story 的业务描述当作操作生产数据的授权。

先单独运行受影响用例，再运行因共享能力变更而受影响的回归范围。单独运行必须能自己建立前置条件，不依赖上一个 pytest 用例。保留退出码、通过/失败/跳过数量和必要的截图/Trace；完整静态检查通过不代表 UI 通过。

目标环境不可达、账号缺失或业务未实现时，保留已生成资产和明确阻塞项，不声称验证完成。失败分类为需求/实现差异、定位/等待、业务数据、认证/环境或测试缺陷，证据不足则写未知。

不要通过放宽断言、无条件 skip/xfail 或无限重试让结果变绿。必须使用预期失败时记录真实缺陷、理由和移除条件，仍不计入通过覆盖。重试不能替代修复数据隔离和等待问题。

## 运行证据

完整交付包的逐项判定、证据等级与有范围限制的结论采用 [证据与判定标准](evidence.md)，结构化输入和生成命令见 [交付物](deliverables.md)。下述资产验证记录保留原格式，用交付包/运行 ID 引用完整报告；不能把新报告 schema 强行覆盖已有资产历史。

每次独立运行保留唯一 `run_id`，同一次运行的多个参数、重试或复制产物不算重复独立验证。建议结构：

```yaml
run_id: 实际运行的唯一标识
at: 带时区的实际时间
result: passed
isolated: true
environment: 测试环境标识
role: 实际角色
automation_revision:
  commit: 实际提交号或null
  dirty: true
  files: {}  # 相关自动化文件路径 -> 实际内容哈希
frontend_revision:
  commit: 实际源码提交号或null
  dirty: false
  files: {}  # 涉及的页面、权限等文件哈希
deployment: 已核验的部署版本或明确unknown
asset_ids: []  # 本次实际覆盖的能力/组合
test_results: []  # node_id、result、对应AC；skip/xfail单列
artifacts: []  # 脱敏证据的位置或链接
cleanup: 已完成或未完成的资源说明
```

命令行只引用非秘密配置；凭据和登录态不写入 YAML。归档可记录提交和哈希，无需保存未经脱敏的原始响应或源码副本。未能确认源码与部署一致时如实写未知，不能用本地前端提交冒充线上部署版本。

## 成熟度状态机

| 状态 | 进入条件 |
| --- | --- |
| `candidate` | 已生成或已有实现，但缺乏当前适用范围内的运行证据 |
| `verified` | 当前相关实现至少一次真实执行通过，记录范围、版本和独立性 |
| `mature` | 已验证基础上，有重复独立运行成功、明确数据隔离与清理、当前适用范围及用户对该组合的人工确认 |
| `needs_review` | 需求/实现/关键依赖或适用环境变化，证据失配，或出现尚未解释的失败 |
| `deprecated` | 已明确废弃，保留替代资产和原因，停止推荐使用 |

重复至少意味着两个不同运行 ID 下的独立执行，不把重试、同次参数化或 mock 结果充数；通过次数不证明普遍稳定性。具体业务需要更多回归时按证据决定，不用统一次数替代判断。

用户确认本 Skill 设计不等于确认某个组合成熟。`maturity_approval` 必须记录实际确认的组合 ID、当前实现及依赖指纹、范围、确认时间和可追溯依据。没有人工确认时停留在 `verified`，仍可被后续需求复用，不因等待晋级阻断生成。

有人工复核项时，UI 子能力可以在其明确范围内记已验证；完整组合的晋级还需相关人工项的独立证据。`Passed — human review required` 不能被转换为整个业务链已成熟。

成熟组合的引用、相关源码、前端规则和环境范围变化后将其及受影响的上层组合标记待复核，保留旧运行与确认记录。只有与本次相关且仍适用的证据才可用于恢复状态；不得更新记录中的哈希来把旧运行伪装成新验证。

## 本轮交付

报告需求与源码差异、直接复用/扩展/新增资产、生成但未运行的范围、实际执行的结果和组合状态变更。给出可复现的命令，但不要在没有执行授权时顺手运行它。Git 提交、推送和禅道写回均保持独立授权边界。
