# skill-manager 自身更新

仅在目标包含 `skill-manager` 自身时读取。

## 固定顺序

1. 检查 Git、源码、当前安装内容和部署记录。
2. 只修改仓库中的 `skills/skill-manager`、注册表、变更记录及确有必要的管理工具；目标 Markdown 按操作契约同步至 Obsidian。
3. 更新语义化版本。
4. 先校验 `skill-manager`，再校验全部 Skill。
5. 核对 Obsidian 对应文档与源码一致，展示完整预览并等待 Git 提交确认。
6. 提交后等待 GitHub 推送确认。
7. 推送并核对远端校验后，等待本机部署确认。
8. 部署 `skill-manager`，核对安装哈希和备份记录。
9. 提示用户新建会话，并在新会话显式调用 `$skill-manager 查看自身状态` 验证。

## 禁止行为

- 不直接修改安装目录完成“热更新”。
- 不在源码校验失败时部署。
- 不使用当前会话后续表现证明新版本已经生效。
- 不自动删除旧备份。
- 不在更新自身的同时顺手修改其他 Skill。
- 不因部署成功就自动提交或推送其他未确认修改。

部署后的当前会话仍按照启动时载入的旧 Skill 快照执行，这是正常现象。只有新会话重新发现并读取安装目录后，才能确认新版本被实际加载。
