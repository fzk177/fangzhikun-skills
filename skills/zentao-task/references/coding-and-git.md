# 编码与 Git

仅在阶段二或三读取本文件，并同时遵守项目上下文与适用 `AGENTS.md`。

## 阶段二：确认后编码

1. 读取禅道当前剩余工时，按时间规则计算临时开始时间，先预览再在同一已授权阶段追加 `--apply` 应用 `coding` 记录：

   ```bash
   node "${CODEX_HOME:-$HOME/.codex}/skills/zentao-task/scripts/task_delivery_record.js" \
     --task <任务ID> \
     --phase coding \
     --real-started "<YYYY-MM-DD HH:mm:ss>" \
     --vault "<vault目录>" \
     --repository "<仓库路径>" \
     --branch "<当前分支>" \
     --base-commit "<基线提交>"
   ```

2. 修改每个仓库前记录本地分支、`git status --short` 和基线提交；分别保存前后端仓库基线，用于区分任务改动、原有修改和并发修改。
3. 只修改已确认的仓库和文件。涉及 Java 后端代码时，先完整读取 [$java-backend-code](../../java-backend-code/SKILL.md)，并遵守其编码与分层规范。
4. 完成后检查本次 diff、上下游一致性和意外格式变化，不运行禁止的测试或构建。
5. 只有必要代码改动全部完成后才能进入 Git 核对；分析或编码未结束时不得提前生成提交确认。

## 阶段三：生成 Git 提交预览

在任何 `git add` 或 `git commit` 前，每个涉及仓库执行：

```bash
git -C <repo> branch --show-current
git -C <repo> status --short
git -C <repo> diff --stat
git -C <repo> diff -- <本次任务相关文件>
```

对照编码前基线准确区分：

- 本次任务代码文件；
- 用户原有或过程中并发产生的修改；
- 默认不提交的 Markdown、SQL、JSON、TXT 等非代码文件；
- 无法确认归属的文件。无法准确区分时停止提交准备，不得擅自纳入。

按仓库完整展示：

1. 改动结果：用业务语言说明实现后的行为。
2. 关键数据流：接口、前后端转换、Service、Mapper、数据库或外部依赖变化。
3. 接口与数据库影响：Req/Resp、兼容性、SQL、表结构和上线脚本结论。
4. 验证与限制：实际静态检查、未运行的测试或构建、人工回归事项。
5. 修改文件及 Git 状态。
6. 本次不纳入的无关修改和非代码文件。
7. 当前本地分支。
8. 每个仓库单独生成的中文提交备注。

提交备注沿用仓库任务风格：

```text
<类型>（<中文影响范围>）task#<任务ID> <准确描述本次交付后的结果>
```

- 新功能用 `feat`，错误修正用 `fix`，只调整结构且行为不变用 `refactor`；用户已指定类型时不得擅自改变。
- 影响范围使用从任务标题和代码范围提取的简短中文，例如“航次执行”“收款认领”，不使用“功能优化”等泛化内容。
- 描述保持单行、具体，不写“完成需求”“任务完成”“问题修复”等空话。
- 分仓库描述各自实际改动。用户已给出准确备注时原样优先，只修正明显缺失的成对引号或括号并说明。

展示后提供：

```text
1. 确认代码，并按上述文件、分支和备注分别提交
2. 确认代码，但本次暂不执行 Git 提交
3. 继续修改代码

回复 $zentao-task 1、$zentao-task 2 或 $zentao-task 3；有其他想法直接描述。
```

该预览只代表本地提交准备，不等同于禅道完成确认；此阶段禁止写禅道。

## 用户选择后的处理

1. 选择 `1` 后，提交前再次检查各仓库分支、状态和相关文件差异；分支、内容、范围或备注变化时确认失效，必须重新预览。
2. 只按显式文件路径暂存，不使用 `git add .`、`git add -A` 或其他宽泛命令；非代码文件只有用户明确要求且属于本次交付时才能加入。
3. 不同仓库分别本地提交；不跳过 Git hooks，不推送，不设置或修改 upstream。
4. 提交后按仓库展示分支、提交哈希、最终备注和剩余未提交文件。Hook 改动文件或提交失败时报告真实状态，不扩大暂存范围或改写备注重试。
5. 选择 `2` 时不执行 Git 写操作，保留工作区并记录“代码已确认、本次暂不提交”。
6. 选择 `3` 或用户提出修改意见时返回阶段二；完成修改后重新生成完整预览，不复用旧选择。
7. 提交成功或明确暂不提交都视为代码确认，以该次选择当下作为实际完成时间进入阶段四。
