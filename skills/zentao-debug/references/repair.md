# Bug 修复流程

仅在用户明确要求修复当前 Bug 时执行本流程；分析、定位或排查不授权修改代码。

1. 修改前记录每个涉及仓库的当前分支和工作区状态：

   ```bash
   git -C <repo> branch --show-current
   git -C <repo> status --short
   ```

   同时读取 `bug-delivery.md`，使用本次临时目录中的 `bug-<ID>-summary.json` 预览 `fix-authorized` Bug交付记录；用户对修复方案的授权同时授权写入本地交付档案，但不产生 Git、测试或禅道写入权限。应用时记录仓库、分支、编码前基线和当前 Codex Session。

2. 用初始状态区分本次 Bug 改动、用户已有改动和过程中出现的并发改动。保留不属于本次修复的修改；无法准确区分时停止提交准备并说明，不得覆盖、回退或纳入提交。
3. 前后端属于不同 Git 仓库时分别记录和处理，不得合并成一次提交。
4. 只修改与当前 Bug 直接相关且已获授权的代码。排查阶段只读的前端代码，此时才可以在授权范围内修改。
5. 修改 Java 后端代码前完整读取 [$java-backend-code](../../java-backend-code/SKILL.md)，并遵守其编码、分层和静态复核要求。
6. 代码改动完成且没有剩余必需修改后，读取 `commit.md` 并进入 Git 提交核对；不得直接暂存或提交。
7. 修复完成但尚未提交时，可把 Bug交付阶段更新为 `local-fixed`，并准确记录已执行验证、未运行测试和剩余风险；不得把静态检查写成 QA 或业务验收通过。
