# 发现消费者并展开场景

在建立模型及交付前的遗漏审查时读取。适用于所有需求；下列类型是探索线索，不是每个需求都要生成的固定测试项。先发现真实关联，再设计场景。

## 从两个方向发现，不能只记录已经想到的消费者

从变更入口读取请求/响应、对象身份、状态和直接共享代码，抽取可搜索的业务/API/字段种子。先沿写入路径看产生和改变了什么，再反向检索这些对象/字段/API由哪些入口读取、过滤、转换、展示、计算或继续写入。只搜索页面目录或按钮名不足以解释持久化对象的影响。

定向覆盖适用的主数据与明细身份、状态判定、源记录/当前结果/历史快照、集合成员和关联生成。跨页面/跨流程共享同一对象或状态时，读取消费者自身的入口、转换及保存/提交路径；“相同组件”或“搜索命中”不等于已解释其业务。财务、审批、导出等名称仅在真实命中或需求明确涉及后才展开。

检索记录应包括种子、执行的query与scope、证据位置、命中/空结果/受限事实及impact ID。不能拿计划中的搜索填作已执行；命中太多应按数据流定向收敛并说明取舍，不能将输出截断当没有其他消费者。对发现的入口说明接受哪些对象/状态、输出到哪里、是否具有写入副作用；无法取得产品规则时仍登记消费者及候选检查。

停止发现需要解释关键对象的身份、转换及直接消费者；共享链继续到已解释边界、范围外或有证据的无影响点。材料不足是具体缺口，不是自动停止全部分析的理由。纯文案/样式/局部交互可用局部证据说明不涉及持久化和其他读取者，不强造全链路。

## 以分支形成用例，问题不替代分支

先写“对象阶段/条件 → 一个业务命令 → 目标结果/不变项”，再按可独立判定的分支形成用例。可参数化等价场景，但保留各参数的前置和预期；不同成功/失败终态、不同消费者、不同权限命令不能只写成“新增修改删除均正确”或一条“生命周期待确认”。数量根据实际分支而定，无最少条数要求。

把动作按其语义区分：编辑字段、替换引用、暂存、确认/提交、取消操作、删除对象、撤回/驳回、放弃未保存编辑。只选择本需求实际可达的动作，不能从命名推定它们的效果相同。尤其同样显示只读的原因，可能只禁止字段编辑而不禁止更换关联；分支分别求证，不扩张禁止范围。

对适用的状态维度检查：动作前、成功后、失败后、重入后，以及状态变化中的旧页面。多步链按成功前缀定位失败后留下的对象与状态。关系类需求检查身份和集合，不仅数量；共享对象类需求区分来源、目标、其他使用者和历史；数值类需求区分输入边界、计算、舍入和派生传播。已知高风险组合需明确设计，不用低风险成对组合替代。

新功能还需识别会被它影响的现有合法行为、不变项和相邻入口。根据现有确认规则设计回归，不因需求未逐字重述每个旧按钮就全部删除。缺少旧规则证据时写明所需基线和候选预期，不能把实现直接当正确性证明。

## 未知预期仍然保留可评审的设计

区分四件事：消费者是否发现、场景是否展开、预期是否确认、测试是否实现/执行。未知不能把前三者压成一条问题清单。

- 有一部分已确认：拆出能独立判定的检查；只将未知的副作用或精确状态保留pending，不拖累无关断言。
- 有合理候选：写具体对象、操作、候选结果及其依据，明确“待确认假设”。例如“同一来源的第二次提交是否应复用既有结果而不新增重复关联”，并列输入、前态、动作和需观测的身份/数量；不能直接断言产品保证了幂等。
- 有互斥解释：分别写候选或同条明确列出替代结果及区分观察点，问题聚焦于哪项规则控制预期；不选择其中一种冒充确认。
- 只有规则缺失：至少给出具体前置/动作/消费者、需记录的对象与决定性问题，不写“准备数据→执行→按规则核对”这种无法评审的占位用例。无法提出具体分支时保留uncovered并解释，不伪造成已设计场景。

候选推导可以来自需求影响、源码路径、历史或项目惯例；必须显式记录其性质，不得通过更换材料kind将它升级为确认规则。已确认通用约束可以按逻辑应用于具体状态，记录推导链和适用前提；要求独立依据不等于每一条具体断言都必须有一段逐字对应的需求正文。

## 另一轮遗漏审查及结束条件

初稿完成后，换入口从实际消费者和条件/命令分支回查，不只读生成的模型和用例。复杂状态/共享数据变更宜用独立上下文做这轮审查；只提供本轮原始材料、获准源码、初稿和技能，不提供QA留出答案或历史对比结论。没有代理时采用同等的第二遍反向检查并如实记录方式。

保留 `discovery-review.md`：实际核对的入口/条件、初稿指纹、发现的遗漏或不适用依据、追加/拆分/保留/废止决定、仍未调查的边界、最终指纹。即使没有发现也写核对证据；不填“已全面检查”等空结论。优先修复分支消失和消费者未发现，再处理格式。语义审查不是给生成模型盖章，结构脚本只能核对已登记内容。

不设目标用例数，不看答案反复调整到达某个覆盖比例。按当前授权和材料完成发现、分支展开、遗漏审查后冻结交付；不可执行项保留。对比留出QA后，只报告差异和通用改进线索，不回写这次冻结用例。已知留出样本参与过技能开发，因此只能称“答案隔离的回放评估”，不能宣称未见需求上的独立泛化证明；后续需新需求验证。
