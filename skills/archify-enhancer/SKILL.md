# Archify Obsidian 增强器

## 目标

复用 `$archify` 的建模、渲染、校验、交付和视觉检查能力，只增强项目归属判断、Obsidian 落盘、文件命名及产物隔离规则。

本 Skill 不复制、不修改 Archify 内核。进入任务后必须加载并遵守当前安装的 `$archify`；若依赖不可用，停止生成并说明缺失依赖。Archify 的图表类型、事实约束、质量门槛和交付回执仍是权威规则；只有输出目录、文件命名和资源隔离与本 Skill 冲突时，以本 Skill 为准。

## 启用条件

- 仅在用户显式使用 `$archify-enhancer` 或明确要求使用此 Skill 时启用。
- 不因普通架构分析、普通 Archify 请求或当前目录位于 Obsidian Vault 而隐式启用。
- 用户显式调用本 Skill 后，加载作为内部依赖的 `$archify` 不需要再次确认。

## 固定目录

项目根目录固定为：

```text
${HOME}/Library/Mobile Documents/iCloud~md~obsidian/Documents/icloud仓库/04.项目
```

运行时展开 `${HOME}`，规范化路径，并确认结果仍位于上述 `04.项目` 根目录内。不得把个人用户名、展开后的绝对路径或其他本机账号映射写入 Skill 源码、图表语义 JSON 或 Git 历史。

每个归属目录按图表类型使用以下结构；只创建当前任务实际需要的图表目录和资源目录，不为一次任务预建全部目录：

```text
04.项目/<归属目录>/
├── 01.系统架构图/
│   └── <可读图表标题>-<YYYYMMDD>.html
├── 02.工作流程图/
│   └── <可读图表标题>-<YYYYMMDD>.html
├── 03.时序图/
│   └── <可读图表标题>-<YYYYMMDD>.html
├── 04.数据流图/
│   └── <可读图表标题>-<YYYYMMDD>.html
├── 05.生命周期图/
│   └── <可读图表标题>-<YYYYMMDD>.html
└── archify-resource/
    └── <可读图表标题>-<YYYYMMDD>/
        ├── candidate.json
        ├── *.json
        ├── *.png
        └── 其他中间产物、导出文件与检查证据
```

Archify 图表类型与目标目录固定映射如下：

| 图表类型 | 目标目录 |
|---|---|
| `architecture` | `01.系统架构图/` |
| `workflow` | `02.工作流程图/` |
| `sequence` | `03.时序图/` |
| `dataflow` | `04.数据流图/` |
| `lifecycle` | `05.生命周期图/` |

不得把 `workflow`、`sequence`、`dataflow` 或 `lifecycle` 继续写入 `架构图/`、`01.系统架构图/` 或其他不匹配目录。旧版 `架构图/` 仅作为历史目录识别，不再作为新产物目标。

## 文件命名

日期使用本机当前日期。最终 HTML 使用以下格式：

```text
<可读图表标题>-<YYYYMMDD>.html
```

`<可读图表标题>` 必须让用户在 Obsidian 文件树中不打开文件也能理解内容，优先表达“系统或产品 + 业务范围 + 分析主题 + 图表用途”。用户明确给出的文件名或标题优先；否则从用户请求和图表 `meta.title` 提炼简洁标题。不得默认使用纯英文项目标识、kebab-case 或 `architecture`、`workflow`、`sequence` 等内部类型代码拼接文件名。

图表页面标题与文件标题应尽量一致，但可以保留正常排版空格；文件名不要求机械复制页面标题。产物名称固定为最终 HTML 去掉 `.html` 后的文件名，资源目录必须使用同一产物名称。例如：

```text
04.项目/01.经营系统/03.时序图/VesselHub内贸OP航次:新增至保存提交时序-20260906.html
04.项目/01.经营系统/archify-resource/VesselHub内贸OP航次:新增至保存提交时序-20260906/
```

文件标题去除首尾空白后不得为空，不得是 `.` 或 `..`，不得包含 `/`、NUL 或产生路径逃逸。示例中的半角冒号 `:` 允许保留。若用户给出的名称包含不安全字符，先说明替换结果再生成，不得静默改成难以识别的英文 slug。

## 归属判断

在写入候选 JSON 或创建输出目录前，先确定唯一归属。按以下优先级判断，命中后不再扩大扫描范围：

1. 用户在当前请求中明确指定的 `04.项目` 下直属目录。
2. 当前会话中，用户已经为同一系统或项目选择过的归属目录。
3. 用户提供的既有产物路径、当前工作目录或当前代码仓库路径已经位于某个 `04.项目/<归属目录>/` 内。
4. 仅查看 `04.项目` 的直属目录名，以及各直属目录下五个标准图表目录、`archify-resource/` 和旧版 `架构图/` 的相对路径与文件名；同一稳定系统名称或可读图表标题只在一个直属目录出现时，复用该目录。
5. 当前系统或项目名称与一个直属目录名称存在唯一、明确的名称对应时，使用该目录。不得只凭宽泛业务词、猜测或历史常识建立归属。

不得为判断归属读取无关个人笔记或遍历整个 Vault 的文件内容。证据指向多个目录、只有模糊匹配或没有匹配时，必须暂停生成，让用户选择，不得猜测。

选择列表按直属目录名称排序并编号，最后追加“其他目录”，例如：

```text
1. 01.经营系统
2. 02.船管系统
3. 其他目录
```

用户可以回复编号或目录名。选择“其他目录”后，让用户输入要创建的直属目录名；名称去除首尾空白后不得为空，不得是 `.` 或 `..`，不得包含 `/`、NUL 或产生路径逃逸。只创建用户确认的直属目录以及所需的 `架构图`、`archify-resource` 子目录。

## 生成与交付流程

1. 根据用户请求确定系统或项目标识、图表类型和事实来源；无法唯一确定图表内容时按 Archify 规则处理。
2. 按“归属判断”确定唯一目录。需要用户选择时，在得到答案前不得创建候选、目录或最终 HTML。
3. 按图表类型确定唯一目标图表目录，并检查该目录现状。目录可以保存多个不同名称的常规 HTML，但不允许 JSON、PNG、截图、回执、临时文件、子目录或其他辅助产物。其他 HTML 不阻断新建任务；只有目标同名 HTML 冲突时才按“既有文件保护”处理。
4. 在 `archify-resource/<产物名称>/` 中创建 Archify 候选 JSON，并在此目录保存所有中间文件、导出资源、校验回执和浏览器检查证据。遵循 Archify 的 artifact-first、更新提示、校验、修复和冻结规则。
5. 使用 Archify 的 `deliver` 生成最终 HTML。需要 Archify 在 HTML 同目录生成私有快照或 sidecar 时，可以先生成；成功后只把本次命令新建的非 HTML 文件移动到对应 `archify-resource/<产物名称>/`，不得移动或覆盖运行前已经存在的文件。
6. 对最终 HTML 执行 Archify 要求的 `visual-check` 和视觉审阅。检查过程产生的 PNG、JSON、WebP、SVG、WebM、日志或其他证据全部保存或移动到资源目录；不得为清理目录而删除交付证据。
7. 最后核对目标图表目录：目标 HTML 必须是唯一同名的常规文件，目录内只允许常规 `.html` 文件，不得存在其他类型文件或子目录；同时核对最终 HTML 与 Archify 成功交付回执中的 SHA-256 一致。未同时满足时不得宣称交付完成。

## 既有文件保护

- 新建任务不得覆盖同名 HTML。用户明确要求更新或替换该图时，才允许由 Archify 的原子交付流程替换同一路径。
- 目标图表目录已有其他名称的 HTML 时予以保留，可以继续生成本次目标，不得为满足“唯一最终产物”而删除或迁移其他图表。
- 目标图表目录已有同名 HTML 时，不得擅自覆盖；先展示相对文件名，让用户决定更新现有图或使用另一个可读标题。
- 目标图表目录已有非 HTML 文件或子目录时，只能自动迁移本次运行新生成的内容。运行前已有内容属于用户，停止清理并请求处理方式。
- 发现旧版 `架构图/` 时不得自动批量迁移历史文件；只有用户明确指定迁移对象、目标类型和新名称后，才允许逐项移动，并保留相应资源与回执证据。
- 不使用宽泛删除、批量覆盖或目录重建来满足“目录干净”。
- `archify-resource/` 可以保留多个按产物名称隔离的资源目录，不因生成新图清理历史资源。

## 输出约束

- 最终 HTML 固定写入图表类型对应的编号目录；JSON、PNG、JPEG、WebP、SVG、WebM、截图、私有快照、回执和其他辅助文件固定写入同一归属目录的 `archify-resource/<可读图表标题>-<YYYYMMDD>/`。
- 最终 HTML 默认不加入 Git；资源文件同样默认不加入 Git，除非用户明确要求。
- 向用户展示路径时优先使用从 `04.项目` 开始的可读相对路径；需要提供可点击路径时可以使用运行时绝对路径，但不得把该绝对路径写回公开源码。
- 不为满足目录约束降低 Archify 的 showcase 校验、浏览器证据或视觉审阅标准。

## 完成标准

结果必须包含：

1. 采用的归属目录及判断依据。
2. 图表类型和唯一最终 HTML 路径。
3. `archify-resource/<产物名称>/` 路径及其中的资源类别摘要。
4. Archify 的校验、交付回执、浏览器证据和视觉审阅状态；不得把其中一项冒充另一项。
5. 目标图表目录只含常规 HTML、没有辅助文件或子目录，且目标同名 HTML 唯一的检查结果。
6. 是否覆盖既有 HTML，以及全部生成物是否加入 Git。
